## データを共有して管理する

データベースは目的に沿って整理したデータの集まり、DBMSはその定義、検索、更新、制御等を担うソフトウェアです。関係データベースは表（関係）を基本に扱います。行はレコード、列は属性です。NoSQLには文書型、キー・バリュー型等があり、用途や整合性の要件を比較します。

## 識別と関連を決める

主キーは各行を一意に識別し、NULLや重複を許しません。複数列を組み合わせる主キーもあります。外部キーは他の表等との参照関係を表し、参照整合性を保つのに使います。ER図は実体と関連を示し、1対多や多対多を整理します。多対多では中間の表を使う設計などを考えます。

## 例：顧客と注文を分ける

| 表       | 主な列                                       |
| -------- | -------------------------------------------- |
| 顧客     | 顧客ID（主キー）、氏名、住所                 |
| 注文     | 注文ID（主キー）、顧客ID（外部キー）、注文日 |
| 注文明細 | 注文ID・行番号（組合せ主キー）、商品ID、数量 |

注文ごとに住所を無条件で重複保存すると、同じ顧客の住所変更が一部だけ反映される更新異常が起こり得ます。ただし注文時点の届け先を履歴として保存するなら別の意味です。属性の意味と時点を決めることが先です。

## 正規化と検索

第1正規形では繰返し項目等を整理し、以後はキーへの依存関係を考えて表を分けます。第2正規形では部分関数従属、第3正規形では推移的な依存に着目します。正規化は重複や更新異常の低減を目指しますが、表を分けるだけでは十分ではありません。インデックスは検索を助ける一方、記憶領域や更新処理の負担もあります。

## まとめ

データが何を表すか、何で識別するか、どの情報に依存するかを順に確認します。
