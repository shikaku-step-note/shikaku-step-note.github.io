## 日数の足し方は作業のつながりで決まる

施設の予約システムを更新します。調査の後に画面と台帳を別々に作り、両方が終わってから接続を確認します。人員と機器は作業同士で取り合わず、始められる作業はすぐ始められるとします。開始時点を0日とし、4日間の作業を開始すると時点4で終わる数え方を使います。

| 作業 | 日数 | 待つ作業 |
| --- | ---: | --- |
| A 調査 | 3 | なし |
| B 画面 | 4 | A |
| C 台帳 | 6 | A |
| D 画面確認 | 3 | B |
| E 接続確認 | 2 | C、D |

## 最短日数と余裕を求める

前進計算では、直前作業が全て終わる時点を求めます。Aは時点3で終わります。Bは時点3から7、Cは時点3から9、Dは時点7から10です。Eは最大値の10から始めて12で終わります。A–B–D–Eが12日、A–C–Eが11日です。全作業を直列に足すと18日になり、並行作業を見落とします。

後退計算では期限の時点12から戻ります。Eは時点10までに始める必要があります。Dは時点7まで、Bは時点3までに始めます。Cは時点4までに始めれば、6日かかってもEの開始に間に合います。AはBとCの早い方に間に合う必要があるので、時点3までに終えます。

| 作業 | 最早開始 | 最遅開始 | 全体の完了を遅らせない余裕 |
| --- | ---: | ---: | ---: |
| A | 0 | 0 | 0 |
| B | 3 | 3 | 0 |
| C | 3 | 4 | 1日 |
| D | 7 | 7 | 0 |
| E | 10 | 10 | 0 |

合流の前進計算は最大値、分岐の後退計算は最小値を選びます。前者は全ての前提の終了を待つため、後者は一番早い締切を守るためです。

## 工期を縮めたら最長経路を計算し直す

期限が時点10に前倒しになりました。Bは最大2日、Cは最大1日まで短縮できます。Dは変更しません。

- Bだけを2日短縮すると、A–B–D–Eは10日、A–C–Eは11日です。全体は11日で、期限を満たしません。
- Bを2日、Cを1日短縮すると両経路が10日です。期限を満たし、どちらの経路も遅らせられません。
- Bを1日、Cを1日短縮してもB側は11日なので間に合いません。

「元のクリティカルパスを2日縮めたから全体も2日縮まる」とすると、途中で別の経路が全体を決めることを見落とします。短縮案ごとに全部の経路を照合し、必要なら品質や追加費用も別に比較します。この例では費用資料がないので、最も安い案までは判断できません。

### 短縮費用まで比べる

別の案件では、同時に進む二つの経路が14日と12日で、期限は11日です。前者は1日につき2万円で最大4日、後者は1日につき3万円で最大2日短縮できます。作業を短縮しても、ほかの経路の日数や品質は変わらないとします。期限に間に合わせるには、前者を最低3日、後者を最低1日短縮します。費用は3×2万円＋1×3万円＝9万円です。いずれの経路も必要日数を超えて短縮すれば費用だけが増えるので、これが最小です。作業を両経路で共有する場合は、一つの短縮が両方に効くことがあるので、経路別に費用を足す前に依存関係を見直します。

## 新しい条件で解く

Aが2日、Bが7日、Cが4日、Dが2日、Eが1日になったとします。つながりは最初の表と同じです。Bを4日短縮できる場合、全体は何日縮まりますか。

<details><summary>途中の計算を確認する</summary><p>当初はA–B–D–Eが2＋7＋2＋1＝12日、A–C–Eが2＋4＋1＝7日です。Bを4日短縮するとB側は8日、C側は7日。全体は12日から8日へ4日縮まります。この例では短縮後もB側が最長です。Cが6日ならC側は9日となり、全体の短縮は3日にとどまります。</p></details>

## 解き直すときの確認

各作業が何を待つかを書き出します。前進で最短日数、後退で余裕を計算し、短縮案では作業時間を置き換えて合流点を再計算します。
