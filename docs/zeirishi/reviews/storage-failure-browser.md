# 保存が制限される場合の回復手段

2026年10月27日、実際の学習者データを含まない隔離ブラウザ環境で、保存APIだけを試験用に失敗させた。

- IndexedDBを利用できない場合に、代替のブラウザ保存へ移り、状態が再読み込み後も残る。
- 両方の保存方式を最初から使えない場合に、一時記録であることと、ページ移動・再読み込みで失うことを表示する。保存したという成功通知へ置き換えない。
- 保存不能時の警告に、その画面の記録を直接エクスポートするボタンを追加した。従来の「マイ学習から」の案内だけでは、通常のページ遷移で一時記録を失うため、現画面からダウンロードできるよう修正した。
- 起動時の保存は成功した後でIndexedDB書込みと代替保存の両方を失敗させた場合にも、保存失敗の通知と直接バックアップを確認した。
- 完全保存不能の状態では再読み込み後に記録が消えることも確認し、保持できるという表示をしていない。警告と直接書出しは320ピクセルでページ全体の横はみ出しがなかった。

保存不能時と途中書込み失敗時の二つの実ダウンロードを独立に読み、バックアップv5で対象の完了状態が含まれることを確認した。これらは試験用のAPI故障であり、全てのブラウザ設定、OSの容量不足、実機故障を再現したとの意味ではない。

詳細は制作環境 `work/zeirishi-upgrade/checks/browser-storage-failure-result.json` と、対応する二つの合成バックアップに保存する。学習記録を外部へ送る処理は追加していない。
